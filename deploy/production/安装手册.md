# Windows x64 + Oracle 生产安装手册

2026-09-23更新：当前完整包默认使用本地Qwen嵌入+Qwen重排，并保留BGE切换。完整数据/权重接入顺序以[本地模型与完整数据接入](本地模型与完整数据接入.md)为准；下面HTTP模式是可显式选择的兼容路径，不是当前本机链路的默认替代。

交付版：`0.1.0-production.20260923`；编制日期：2026-09-21。应用基线：`v0.1.0 / 8d8526f143c402a2bd563dcd678c84e76b0f2aad`。

## 1. 先判断能否安装

这是生产配置的**联网构建安装包**，含完整应用源码、锁定的 Python/npm 依赖清单、已编译前端、Oracle Alembic 迁移、Windows 操作入口、预检和知识库迁移方案。不是 Windows 原生 exe，也不是已经装好数据库和模型的离线镜像。

如果另收到 `fundkb-linux-amd64.tar`、`image-manifest.json` 和对应 `SHA256SUMS`，才可跳过联网构建，走镜像导入。包内 `PACKAGE.json` 记录实际交付类型；不要把构建脚本当成已构建镜像。

必须具备：

| 项目 | 本安装版边界 |
| --- | --- |
| Windows | x64；Windows 10/11 上使用满足官方要求的 Linux 容器引擎。Windows Server 不支持 Docker Desktop，应使用机构批准的 Linux VM + Docker Engine；参见附录，不要临时切换全机容器模式。 |
| Docker | 服务端必须是 `linux/amd64`；Compose >= 2.30.0；安装器不安装/卸载 Docker、不改全局运行策略。 |
| Oracle | 外部 Oracle **12.2 或更新版本**，建议机构仍受支持的版本；独立应用 schema、UTF-8 字符集。驱动 Thin 支持 12.1，但本安装版因长标识符等应用 DDL 边界保守要求 12.2+。11g 不在本包可直接上线范围，不能伪装兼容。 |
| 登录 | 机构 OIDC issuer、client ID、client secret、首位管理员真实 subject；本生产版无演示账号。 |
| 入口 | 域名、可信 HTTPS 完整证书链和对应私钥；SSO 回调须准确配置。 |
| 嵌入 | 已部署的 OpenAI-compatible `/v1/embeddings` 服务及准确模型名、修订号、维数。默认模板 Qwen3-Embedding-4B/2560，不会偷偷退回 hashing。API 镜像不内置模型权重。 |
| 网络 | 联网构建需访问镜像仓库和 PyPI；运行需访问 Oracle、OIDC、批准的模型服务、ClamAV 更新源或机构镜像。离线模式也必须解决病毒库更新。 |

单机资源规划起点（**不是已测容量结论**）：8 vCPU、16 GB RAM、100 GB 可用 SSD + 文档增长空间；建议 16 vCPU/32 GB。ClamAV 单独预留约 4 GB。以上不包含本地大模型推理服务器的资源。API 单进程、worker 两个进程；不要未验证就横向扩 API（OIDC 临时状态目前在进程内）。

架构：HTTPS Nginx → API → Oracle；worker 经 RabbitMQ 执行持久任务；Qdrant 保存独立指纹的向量；ClamAV 经内部流式扫描检查上传文件。只有 HTTPS 入口映射主机端口；Oracle 是外部已建服务，不会新建或修改你的数据库实例。

## 2. 解包和配置（Windows PowerShell）

建议把安装包解压到 `C:\FundKB\releases\0.1.0-production.20260923`，配置放在 `C:\ProgramData\FundKB\production`。配置、日志和数据不要放在发布目录或 Git 仓库。脚本为源码交付，按机构策略签名/批准执行；不要为本项目关闭整机脚本策略。

```powershell
Set-Location C:\FundKB\releases\0.1.0-production.20260923
.\Deploy.ps1 -Action Verify
.\Deploy.ps1 -Action Init -ConfigDir C:\ProgramData\FundKB\production
```

`Init` 仅创建新目录，生成各自随机的加密主密钥、RabbitMQ 密码和 Qdrant key，并限制 NTFS 访问权限。**已有目录将拒绝覆盖**。后续升级不要再次 Init；主密钥遗失将无法解密已保存的模型连接凭据。

编辑新目录中的 `settings.json`：

- `database` 填主机、监听端口、**service_name 而非 SID**、专属用户名/密码。保持 JSON 转义规则；脚本用 SQLAlchemy 编码，不要求你手工 URL 编码密码，不经过 shell 执行。
- `site_url` 和 `FKB_ALLOWED_ORIGINS` 填同一 HTTPS origin。非 443 端口须两处一致，并传 `-HttpsPort`。
- OIDC 回调：`https://你的域名/api/v1/auth/callback`；请以源码路由及实际 `Check/Doctor` 后登录验证为准。禁止登录到演示用户；管理员 subject 是 IdP 返回的 `sub`，不是邮箱猜测值。
- `FKB_EMBEDDING_BASE_URL`、模型名、维数、修订号与真实嵌入端一致；在机构确认资料传输范围后将 `FKB_EMBEDDING_ALLOW_DOCUMENT_TRANSFER` 改为 `true`。
- 默认 `hybrid` 保留 Wiki + 图谱 + BM25 + 向量协同链路。若暂时无法部署向量服务，应由你明确改为 `wiki`，并记录该能力暂未启用，不属于完整混合检索验收。
- 当前 API 镜像安装已锁定的torch/transformers及语义依赖。权重由内部完整包单独恢复；默认`Init -ModelMode Local`使用CPU重定位配置，保持Qwen重排。`-ModelMode Http`才选择旧HTTP模板。不能照搬MPS路径或将本机速度视为CPU生产速度。
- 生成模型在网页“我的模型”中按用户重新配置并授权。安装预检**不调用任何生成/嵌入模型**。本机 Codex OAuth 身份文件不会被打包；生产 Linux 下 Codex bridge 需独立部署、重新授权及验收，本版不宣称已验证它。

把证书链和私钥分别放入 `tls\fullchain.pem` 和 `tls\privkey.pem`。私钥不要传聊天、写入仓库或发普通邮件。使用内部 CA 时，浏览器和容器都必须信任机构 CA，不能用关闭证书校验代替。

## 3. 准备镜像（二选一）

### 联网构建

```powershell
.\Deploy.ps1 -Action Build -ConfigDir C:\ProgramData\FundKB\production
```

此步骤在本机 Linux amd64 Docker 引擎编译 API，前端使用已编译静态资源；安装器拉取 RabbitMQ/Qdrant/ClamAV。首次构建时间受网络影响，不承诺下午现场一定能拉完。不要在生产时间窗口首次验证外网可用性。

### 在联网准备机导出，隔离区导入

联网准备机先执行 Init（保留占位符，不填生产秘密）、Build，然后：

```powershell
.\Deploy.ps1 -Action ExportImages -ImageDirectory C:\FundKB\image-handoff-20260921
```

传递完整镜像目录和安装包，经机构扫描后在目标机运行：

```powershell
.\Deploy.ps1 -Action LoadImages -ImageDirectory D:\handoff\image-handoff-20260921
# 后续所有操作沿用同一目录，例如：
.\Deploy.ps1 -Action Check -ImageDirectory D:\handoff\image-handoff-20260921
```

镜像导出包含五个镜像的具体 ID、摘要和 Linux/amd64 结果，以及 `offline.compose.yaml`。Docker save/load 不能依赖原 registry digest 一定被恢复，因此离线包用固定本地别名并在每次启动前核对 image ID，不自动从公网补拉。后续 Check/Services/Doctor/Migrate/Start 都需传同一 `-ImageDirectory`；若整个镜像目录放在安装目录的 `images` 中则自动识别。不包含数据卷、业务资料、配置或权重。SHA256 可检测损坏，不等价于发布者数字签名；应使用可信交付渠道核对外部哈希。

## 4. 检查、建表、启动

先让 DBA 按 `Oracle与运维准备.md` 准备专属空 schema 和备份；首次建表和未来更新均是明确数据库动作，不能仅因容器启动就自动执行。

```powershell
.\Deploy.ps1 -Action Check
.\Deploy.ps1 -Action Services
.\Deploy.ps1 -Action Doctor
# DBA 确认专属空库或已备份后才执行；Oracle DDL 可能自动提交。
.\Deploy.ps1 -Action Migrate -AcknowledgeDatabaseChange
.\Deploy.ps1 -Action Start -BindAddress 服务器监听IPv4地址
.\Deploy.ps1 -Action Status
```

上面默认配置路径为 `C:\ProgramData\FundKB\production`；如果使用其他路径，每条都加 `-ConfigDir`。将“服务器监听IPv4地址”替换为实际 IPv4；不指定时只绑定 127.0.0.1。不要把企业服务器暴露到公网。后续 Start 必须沿用同一 ProjectName/ConfigDir/BindAddress/HttpsPort。

- `Check`：配置/占位符/生产开关，不连接 Oracle、不调用模型。
- `Services`：启动内部基础服务；首次病毒库载入最多等待 15 分钟，**这是容器就绪等待，不是模型思考时限**。
- `Doctor`：Oracle 连接与表版本、OIDC discovery、Qdrant 鉴权、RabbitMQ 鉴权、ClamAV 合成文本扫描、嵌入地址 TCP。报告不会输出配置值。TCP 成功不代表模型可推理或维数正确。
- `Migrate`：先 Doctor，然后只在空 schema 执行已审核 Alembic；已有未知表、旧版本或残缺迁移会拒绝自动覆盖。已是当前版本可重复检查。
- `Start`：先要求已迁移，再启动应用；不会自动建表、自动拉镜像、自动调用模型。
- `Stop`：只停止当前 project 的应用三项；保留基础设施及所有数据卷。

`Sql` 可输出供 DBA 审阅的当前 Oracle DDL（不执行），不应代替版本化迁移直接反复导入。

## 5. 上线验收，不以绿灯代替业务验证

完成并签字记录 `部署验收清单.md` 后再放行用户。最少应验证：真实 OIDC 登录与安全 cookie、个人/团队隔离、文件扫描上传与完整预览、Wiki/图谱来源点击、重建后的向量数量及指纹、同义问题 BM25+向量召回、真实咨询引用定位、跨页模型选择、取消与失败说明、备份恢复。

没有授权的真实模型调用由运维/你手动发起，结果留内部测试证据，不自动发布知识。未审核资料保持待核验，不能迁移时批量改为已审核。

## 6. 故障和回退

- 配置失败：修正 `CHANGE_ME`、OIDC、HTTPS、维数、传输授权；不要把 APP_ENV 改 development 绕过。
- Oracle 连接失败：从容器网络核对路由/1521/service_name/版本/权限；宿主机能连不代表 Linux 容器能连。不要使用 SYS/SYSTEM。
- ClamAV 不健康：核对病毒库加载、更新时间和联网更新策略；不可禁用扫描后接收真实资料。
- worker 不健康：检查 broker 和项目容器状态；容器网络中 broker 的密码必须与 settings.json 一致。
- 有表却迁移失败：立刻停止，不再重试建表，DBA 检查 Oracle 已提交 DDL 和版本记录。
- 回退应用：Stop → 保留所有卷和配置 → 选择之前经过验收的安装目录/镜像 → 确认兼容相同 schema → Start。**不运行 down -v、prune 或 Alembic downgrade**。
- 回退数据库：独立停写窗口，DBA 恢复对应备份与一致文件快照；恢复后重新核对引用和向量，应用回退不等于数据库回退。

## 附录：Linux VM

Windows Server 上可由运维使用机构批准的 Linux amd64 VM，按同一 Compose 文件部署。配置需在 VM 上独立创建并限制 0600/0700 权限；不要把 Windows 盘符传给远端 daemon。可安装 PowerShell 7 后使用本入口的 Verify/Build/Check/Doctor 等操作，但 Init 仅支持 Windows ACL，因此 Linux 的配置与密钥应由机构秘密管理器生成。严禁使用示例占位符上线。尚未确认你的具体 Windows 版本，不能把此替代路径写成已经验收。
