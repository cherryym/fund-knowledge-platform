# 当前完整链路：本地模型与数据接入

2026-09-23。本章覆盖旧安装记录中“轻量镜像不含本地模型依赖、默认关闭重排”的描述。应用镜像现在安装已锁定的semantic/local-models依赖，Init默认Local模式；权重随**内部完整包**交付，不嵌入公共源码或GitHub。

## 当前运行配置

- 默认Qwen3-Embedding-4B，保留BGE-M3独立向量空间与网页切换；BM25保留。
- 两套检索方案都保留Qwen3-Reranker-4B，不能为安装方便静默关闭重排。
- 原始Mac配置、向量与权重全部保留作迁移依据；生产副本生成CPU显式配置，不复制MPS运行环境。
- 精度、修订、tokenizer、归一化、分段策略与指纹不变。路径与设备重定位脚本会计算前后指纹并拒绝变化。**指纹相同不等于跨设备数值/业务质量和时延已经验收。**
- 本版适配器支持CPU/MPS，不宣称已有CUDA推理实现。x64 Linux生产先走CPU路径；CPU没有Mac MPS加速，需实机性能验收。考虑API和worker可能分别加载模型，建议为完整本地模式准备64GB以上内存；这是容量规划建议，不是负载保证。

## 顺序与命令（Windows PowerShell）

先将RAR解开，将`application`内的应用ZIP解压到新的发布目录。下面假设已经进入该应用目录，且同一`ProjectName`始终为`fundkb-production`。

```powershell
.\Deploy.ps1 -Action Verify
.\Deploy.ps1 -Action Init -ModelMode Local
.\Deploy.ps1 -Action Build
```

Build仍需联网取镜像/Python依赖。**内部知识包和权重齐全，不代表包含Docker离线镜像。** 如需要离线，先在批准的联网Linux/amd64 Docker准备机执行Build及ExportImages，再带镜像到目标机；不要把Mac虚拟环境当生产依赖。

恢复内部包时可用随包`restore-private-transfer.py`（需要Python 3.12或更新版本），其目标目录必须不存在。脚本先核对SHA256SUMS，解压后逐文件核对，不导入Oracle、不启用认证、不启动模型：

```powershell
python .\restore-private-transfer.py --package C:\FundKB\transfer --destination C:\FundKB\restored --extract
```

接着把**已核验的脱敏data副本**接入全新的应用数据卷。下面命令拒绝已有非空目标卷；镜像标签以本包`deploy/production/images.env`为准。本次使用独立版本的`fundkb-api:0.1.0-production.20260923`本地构建标签，文件快照与SHA256清单区分版本，不能把旧标签镜像当新构建。

```powershell
docker volume create fundkb-production_app-data
docker run --rm --network none --user 0:0 `
  --entrypoint /app/backend/.venv/bin/python `
  --mount "type=bind,source=C:\FundKB\restored\project\data,target=/incoming,readonly" `
  --mount "type=volume,source=fundkb-production_app-data,target=/app/data" `
  fundkb-api:0.1.0-production.20260923 /app/ops/stage_local_data.py `
  --source /incoming --destination /app/data --ack-empty-volume
```

脚本复制资料与权重到空卷，并新建`/app/data/production-profiles/`，保留原profile不覆盖；生成`qwen3-4b.json`、`bge-m3.json`及`registry.json`。API和worker使用相同配置。容器uid10001获得该新卷文件权限。

**此步骤不是Oracle数据导入。** `data/fund_kb.sqlite3`是脱敏备份，生产API只连接配置中的Oracle。必须按《知识库迁移方案》在独立schema完成逻辑导入、身份映射及对账，才能看到原知识库。不要只建空Oracle表就以为内容已迁入。

## 索引及认证

1. 优先使用随包Qdrant集合快照恢复到同版本服务；先确认目标无同名业务集合，勿覆盖。原始storage目录仅作回退，不能当跨系统恢复已成功的证明。
2. Oracle内向量回执/来源版本与Qdrant集合必须同时核对；不一致时不伪造receipt，应在明确授权下重建。
3. 网页检查两套profile的当前授权覆盖、dirty数量与默认Qwen选择，再做两套方案各一次实际检索验证。
4. 所有模型连接在脱敏副本中禁用，API密钥需在生产重新填写；Codex保持SIGNED_OUT，需另行部署、授权并验收Linux bridge，不能复制本机登录态。
5. OIDC用户映射、HTTPS、Oracle账号和新的应用主密钥必须在生产配置。禁止开demo登录绕过。

目标Windows/Oracle实库、模型CPU速度与跨设备检索质量未在打包机验证；本包只报告实际完成的打包与本地检查。
