# 本机知识库 → Oracle 生产库迁移方案

2026-09-23补充：用户本次明确要求完整私有RAR，业务数据已纳入另行脱敏导出的内部包，包含逻辑表导出及SQLite只读恢复副本；原版应用ZIP自身仍不含业务数据。当前本地模型配置、权重、索引及恢复入口以[本地模型与完整数据接入](本地模型与完整数据接入.md)为准。下面“本次没有导出”等语句是2026-09-21初版应用包范围记录，不代表本次完整RAR遗漏数据。Oracle导入/身份映射依然需要在目标隔离环境按本方案执行并验收。

本次交付的是**迁移方案**，没有导出、复制、删除或更改本机业务数据。应用安装包不含现有文档、Wiki、图谱、用户和索引。迁移执行需要另行确认源快照、目标环境、账户映射和停写窗口。

## 一、不能“拷一个 SQLite 文件就完成”

本机 SQLite 不能作为 Oracle 数据文件挂载；也不能把 Mac 的虚拟环境、MPS 模型路径、Codex 授权目录和 Qdrant 本地目录整体覆盖到生产。数据库、原件存储、模型/索引指纹、身份主体必须分别处理并在同一迁移批次核对。

推荐路径是：一致性只读快照 → 全表/全原件清单 → 依赖与身份映射 → 隔离 Oracle 暂存库演练 → 对账 → 生产停写导入 → 重建索引 → 验收切换。保留源库和回退副本，不直接修改原库。

## 二、迁移矩阵

| 内容 | 处理方式 | 必须保留/核对 |
| --- | --- | --- |
| 文档原件与附件 | 按数据库 `blobs` 对应 storage key 迁移；不照文件名去重 | 每件 SHA256、字节数、MIME、对象 key、版本引用；Windows 路径不写回对象 key |
| 文档/Wiki/Agent 能力 | `resources`、`resource_versions`、`content_blocks`、相关扩展表完整逻辑导入 | 主键、版本号、段落 block_id、顺序、结构化数据、标题/正文、Hash、适用范围、原始状态 |
| 引用与图谱 | `evidence_links`、`relation_edges` 及派生关系/规则效力记录 | 两端 ID、确切来源版本、定位、方向、关系类型、撤销/失效状态；不能只迁可视化坐标 |
| 审核/发布 | `review_decisions`、`releases` | 原始审核人、时间、Hash 和状态；`UNKNOWN/待核验` 不自动改为有效 |
| 分类/空间/权限 | `spaces`、`space_members`、`resource_grants` 及资源分类/标签记录 | 个人库 owner、团队成员、ACL/access epoch；默认不得放开个人库 |
| 历史问答/反馈/审计 | 作为只读历史迁入，按授权范围与数据保护策略处理 | run/evidence/ref 对应关系、原错误和耗时、原时间戳；不把历史失败改成功 |
| Agent 工作流/运行 | 能力定义可迁；历史运行只读保存 | 输入输出 schema、依赖版本、步骤与证据；在途运行不得自动恢复为真实业务执行 |
| 用户身份 | 专门映射本地 user ID ↔ 生产 IdP subject | 不能假定演示账号“李明”就是某个真实用户；保留审计可追溯映射与旧 ID |
| 登录会话/临时上传/队列 | 不作为活跃状态迁入；保留必要历史另行归档 | 不导入 `login_sessions`；不把旧 outbox、pending jobs、idempotency 请求重新投递 |
| 模型 API 密钥/OAuth | 新部署、重新配置/授权；如需迁移加密值则单独密钥迁移方案 | 不复制宿主 Codex 登录态；新主密钥无法解密旧密文，不能带旧密文后声称凭据可用 |
| 向量集合/BM25 缓存 | 优先在 Oracle 导入、来源核对之后**重建** | 模型、revision、维数、tokenizer、切分策略、查询指令、normalization、fingerprint 和全量覆盖 |

表名以发布版 `Base.metadata` 和实际数据库全表清单为准。上表是分组说明，**不是只迁这些名字就视为完整**。所有未知表必须在迁移清单列明“迁入/归档/重建/不迁及理由”，不能静默遗漏。

## 三、执行前冻结清单

1. 在停写或一致性快照机制下生成批次 ID，记录源应用 SHA、SQLite schema 版本、快照时间（UTC/北京时间明确）、全部表的行数/主键清单/规范化内容 Hash。
2. SQLite 使用在线备份 API 或已停写的数据库级快照，不能只拷 `.sqlite3` 忽略 WAL。原件目录需对应同一业务快照；多文件快照不一致时不得导入。
3. 由资源状态确认用户此前主动删减的资料。回收站保持原删除时间、保留策略和法律保全，不擅自恢复，也不迁移时永久清除。
4. 输出引用完整性报告：所有版本/块/文件、图谱两端、规则替代关系必须可解析；保留原有异常，不以丢行消除异常。
5. 导入前先拿到真实 OIDC 账户映射表，至少个人库拥有者、团队管理员和历史审核人完整映射。禁止把所有 owner 改成首位管理员。
6. 备份文件本身属于内部资料；加密后经机构批准渠道转移，密钥分渠道保管。**不放 GitHub Release、Actions Artifact 或公开安装包**。

## 四、隔离演练与正式导入

- 先在独立 Oracle 测试 schema 用同一 Alembic 建表；不得跳过约束，不能使用 SYS/SYSTEM。
- 专用逻辑迁移器按外键依赖拓扑写入。UUID、JSON、UTC 日期、Boolean、CLOB、长中文标题、空字符串与 NULL（Oracle 特有差异）逐项做往返对照；碰到差异停止，不能默认截短或丢字段。
- 能保留原主键的保留原主键；若需身份映射，以明确迁移映射表关联，不允许随意生成新的文档/段落 ID 导致引用失效。
- 按批次幂等导入，记录每表/每批次处理数与校验 Hash。目标已有业务内容时不要“全删再来”，应重新选空暂存 schema 或明确合并规则。
- 将在途模型/扫描/发布任务标记为需运维处理，禁止迁移器自动续跑。历史终态按原样保存。
- 原件恢复到应用数据卷，目录与文件仅对容器 uid 10001 和受控备份进程可读写；扫描器通过 INSTREAM 接收数据，不依赖开放共享卷权限。

**本次没有交付“已在真实源数据验证的 SQLite→Oracle 自动迁移器”，因此不能用本方案冒称数据已可一键迁完。** 实际迁移前必须实现并在该快照与目标版本演练逻辑导入和对账；若下午只装应用，生产库初始为空，这是预期状态。

## 五、向量与本地模型

向量不是可脱离模型随意搬运的通用数值。Qwen3-Embedding-4B 与 bge-m3 的结果不兼容。即使名字相同，从本地 transformers 改成 HTTP 服务也必须对照 tokenizer、query instruction、输入拼接、归一化等；当前系统指纹还包含模式，**不要人为改指纹复用旧集合**。

1. 保留本机 Qwen/BGE 原索引作为回退，不在本次安装中删除它们。
2. 生产默认模板 Qwen HTTP/2560，但必须与机构实际服务一致。若选择 bge-m3，改模型名、1024 维、修订号与真实配置后重新建独立集合，不能只改名称。
3. 将 API 与 worker 指向同一配置、同一 Qdrant；使用网页“Wiki + RAG 检索”明确发起目标库重建，保留完整版本、段落、权限、Wiki/图谱关联。该动作可能消耗嵌入额度，需要授权。
4. 两套结果同时保留/切换要以生产环境独立配置的 retrieval profiles 为准；模板不包含本机绝对路径和凭据。当前轻量安装版默认只配置一个生产 HTTP profile，不宣称自动迁入双模型配置。
5. 核验 eligible 来源数、已索引版本/块数、无效来源和失败数、索引 fingerprint、维数、单位数；不能只看 Qdrant 集合存在。
6. 固定一组跨业务验收问题：停牌、固收回售、国债期货交割、FOF、费用、法规效力等。检查引用是否准确命中规定来源、完整上下文和业务日期；无需预填标准回答绑死模型。
7. 旧向量只有新链路通过全量对账、质量/权限验收和回退期后，才另行授权清理。

## 六、切换/回退判据

- 结构：所有纳入范围表、版本、段落、附件完整；未处理表=0；主外键异常无新增。
- 内容：逐文件 Hash 一致；正文/JSON 往返等价；保留原状态/日期/删除和保全标记。
- 引用：原文定位/反链/图谱两端全量可解析；历史失效引用仍提示失效，不修饰为有效。
- 权限：至少两名真实用户验证个人不可互见、团队成员可协作、已撤权不可访问。
- 索引：所有 eligible 版本覆盖，无静默截断/混用；性能测量含冷启动和跨页点击。
- 运行：SSO、上传/扫描、解析、问答、Agent 调用登记、任务取消和重启恢复通过。
- 恢复：目标 Oracle 备份 + 同一批次原件 + 主密钥受控备份，恢复到隔离环境并完成一次对账。

任何关键项不通过：保持源系统只读/原入口，不切换正式用户；不在用户已开始写入生产后直接回拷旧库覆盖新增资料。
