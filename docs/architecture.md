# 架构与数据边界

## 分层

1. **交互层**：React工作台，文档、知识、答疑、Agent能力和治理页面；以类型化HTTP接口访问服务，不把前端隐藏按钮视为鉴权。
2. **业务层**：FastAPI、SQLAlchemy，处理角色、资源、版本、审核、工作流、模型连接与任务；所有写操作使用约定的CSRF、幂等键和必要ETag。
3. **作业层**：数据库持久化Job及尝试/阶段/租约，local或Celery执行。模型调用、解析、索引和导出不靠单个浏览器连接存活。
4. **内容层**：关系库保存资源、版本、内容块、引用、关系、会话、运行与审计；原件保存在受控文件/对象存储。Qdrant是可重建的检索投影，不是资料唯一副本。
5. **模型层**：每用户连接、显式资料传输许可、协议适配、响应归一化与安全边界。生成模型和嵌入/重排模型分工独立。

## 文档与知识生命周期

- `Resource`是稳定对象身份；`ResourceVersion`维护版本；`ContentBlock`保存结构、原文、locator与内容摘要。
- 原始附件不由在线编辑覆盖。草稿可编辑；冻结版本通过新修订更新，旧引用仍绑定旧确切版本。
- 上传原件、扫描、解析、线上校对、复核/发布分开；上传成功不等于知识有效，模型草稿不自动发布。
- 已发布版本不会被未发布的新草稿遮蔽。删除默认回收；永久清除需满足保留策略、法律保全、权限及依赖检查。
- 个人库仅owner可见编辑；团队库按有效身份与成员角色提供阅读/协作。独立复核与发布职责按后端规则执行。

## 查询链

`wiki_reader / universal`的主要路径：

1. 读取问题和明确业务背景，模型生成公开查证计划；此时不预读本地正文，不要求展示私有思维链。
2. 构建当前用户、空间、业务日期下的授权目录，执行同意图多路搜索：Wiki入口、向量、BM25、重排与已有关系。
3. 将命中的单元定位回真实章节、条款和原块，读取完整相关小节及必要上下文；`READ_SECTION`/`READ_FULL`允许继续查读，而非固定只取前几段。
4. 来源和Wiki均重验权限、删除/停用、扫描、冻结Hash与依赖；生效时间和经人工确认的替代事实独立处理。
5. 为当前读取内容分配E编号，模型综合形成Markdown，允许比较、推断、条件分支与建议，但只能关联本轮真正读过的来源。
6. 返回完整正文、可定位引用、执行记录和明确告警。来源变更后，查询历史也要复查当前可读性；不能继续显示撤权内容。

模型推理与引用定位是两个问题：程序可以检查编号、版本和摘要，但不能据此认证业务推断正确。未登记编号不补造，不把免责声明替代专业审核。

## 切分与向量

语义切分面向章节、条款、段落、表格行，不直接把PDF每一行当独立知识。超长内容按实际tokenizer预算拆开；记录`source_spans`、原块Hash与字符范围，实现回到原文的定位。查询通过候选融合和重排发现来源，相关完整正文读取与候选长度分开。

模型、修订、维度、指令及切分参数形成检索指纹。Qwen和BGE使用独立命名空间，创建咨询时冻结检索选择，运行中不全局切换模型。原文或权限变化需要使对应投影失效/更新。

## 缓存与性能

- 公开计划缓存仅限完全相同请求/用户/空间/模型配置/业务日期，短TTL、有界内存；合格的成功运行才可提供计划。当前来源仍重验，最终答案重新生成。
- 路径缓存保存标识与导航结果，不以缓存授权代替实际读取；目录、政策、指纹变化后不能直接沿用旧路径。
- 前端会话缓存按用户、空间和权限上下文隔离；切换页面不必全部重拉，授权失效必须撤去旧数据。
- 多查询合批、批内复用、Worker图谱和轻量进度轮询减少重复工作；不能靠少读资料或强制结束推理制造SLA达标。

## Agent能力与执行边界

能力定义包含输入、步骤、依赖、来源、工具要求、输出和核对项。运行冻结定义与输入，Agent取下一步、读绑定来源、回报结果；需要人工确认的步骤停在人工检查状态。

MCP只提供受限七工具，不暴露任意shell/数据库/URL代理。Agent声明完成只是一份回报；平台`COMPLETED`也只说明指导流程所要求的记录完成，不证明资金、交易、过账或审批已在外部系统真实执行。

## 数据库与迁移

SQLAlchemy模型为实际结构，Alembic负责迁移；SQLite开发、Oracle/OceanBase目标实例分别验证。动态API扩展以运行时接口和`api_*.py`注册为准，基础OpenAPI合同不是唯一功能清单。表结构编译成功不等于目标数据库实测通过。
