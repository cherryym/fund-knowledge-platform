# 2026-10-02 变更汇总

本次汇总 `9159a36` 之后的代码、合成测试及说明：10-01 接入的推理核心查询策略，以及 10-02 对知识编译、单次综合装载、资料缺口的修正和 Codex 文本合同 v4（单次综合容量）。只记录工程交付，不表示全库业务准确性或目标生产环境已通过验收。

## 推理核心（`FKB_WIKI_QUERY_STRATEGY=reasoning`）

- 规划前提供只含元数据的库地图：概念维度、来源的层级/发布机关/施行·过渡期·废止线索（规则预抽，绑定版本Hash，不改效力字段）、管理员已确认的替代事实、知识页目录；按请求容量分 full/sources/compact 三档。新增只读接口 `GET /library-map`。
- 规划输出 `ISSUE`/`READ`/`SEARCH`/`GAP` 命令行；`READ` 直接入队，大来源按本题在来源内定位读取；不按题型套用主来源规则。
- 综合按上位、现行、专门、公募基金专门规定判断效力；“至某日实施完毕”是实施期限而非失效，`UNKNOWN` 不等于失效；无直接规定时写明推导与前提；以估值技术确定公允价值时说明公允价值层次。
- 已读材料超过一次综合请求时，按“相关原文→知识页→无关原文”三层装载，放不下的大页按完整小节重排取最相关部分；未放入的资料按标题列出供补读。模型要求补读后的下一轮从全部已读材料重新装载（新点名页面优先），不再改走提要路径而丢失上一轮原文。
- `GAP` 只记录本库缺少的规范性资料：点名库内已有资料的不算缺口（包括按“系列——主题”标题的主题和文件类别描述的，如以“公允价值计量准则”指代已入库的准则39号）；合同、托管协议等个案材料单列为“落地前需核对的个案材料”。`GET /coverage-gaps` 汇总缺口（编辑/管理员看空间汇总，读者只看本人运行），均为未核实的模型声明。
- 新增 `FKB_WIKI_SYNTHESIS_REASONING_EFFORT`：只在连接已验证支持时发送综合阶段推理强度。
- 本地嵌入与重排编码器在 MPS 上的前向、迁移和释放经进程级锁串行，避免并发 Metal 断言导致进程退出。

## Codex 文本合同 v4（单次综合容量）

- 新增文本合同 v4（`LARGE_CONTEXT_PROFILE_VERSION`）：在 v3 基础上只放大请求预算——语义内容 64 KiB → 192 KiB，单行 RPC 256 KiB → 1 MiB；无工具、只读沙箱、角色通道与推理强度核验等字段与 v3 相同。v2/v3 配置保持原合同和上限。
- 加载 v4 配置时，要求每个模型的正常探测确实发送过超过 64 KiB（且不超过 v4 上限）的请求；v3 探测记录改版本标签不能冒充 v4。
- 容量判断（`fits_context`）、发送前预检和实际发送都按已加载配置的合同上限；文本推理连接按合同放宽单行上限，认证连接不变。
- `scripts/probe-codex-large-context-v4.py`：复用固定 Hash 的 v3 回环探测流程（本机模拟服务、系统沙箱、零工具与攻击拒绝检查），换用 v4 合同和约 18 万字节的合成请求；只生成新的候选目录，安装是单独步骤。

## Wiki 编译

- 来源上限 8 份调整为 64 份，构建说明与指定段落不设额外长度上限；新增 `multi_batch`（显式类型、单页）：按完整小节分批编译、按结构合并，单批暂时性错误重试一次。
- 分批合并后整页统稿：只删除被本页其他段落反驳的“材料未提供”类句子；只被部分反驳的可“只删字收窄”（程序校验为原句的有序子序列），不改写、不新增，逐条记入 `coverage.page_review`。
- `multi_batch` 每次编译整个范围，不按构建账本跳过；仅关系构建的账本键包含参考节点快照，节点变化后重跑不再被判为“无新内容”。
- 编译规范升为 `wiki-compilation/1.1`：页面标题写主题本身，不加状态说明；SUPPORTED 段不夹带缺口说法，缺口写成独立 GAP 段；“本批/新增材料”等批次说法改写为“本页”。
