# 2026-10-08 变更汇总

本次在 `4c39cdd`（PR #4 合并）之后，修复受控 HTTP 部署下前端生成请求标识的问题。只记录工程交付，不表示目标生产环境已通过验收。

## 背景

用服务器 IP 以普通 HTTP 访问时（不是 localhost，也不是 HTTPS），页面不属于浏览器的安全上下文，`crypto.randomUUID` 不存在。2026-09-30 的修复只覆盖了 `api.ts` 中的请求幂等键，以下 5 处仍直接调用它，操作时会抛出 `crypto.randomUUID is not a function`：

- 上传队列加入文件、恢复队列（`uploadQueue.ts`）；
- 编辑器新建段落（`blockOperations.ts`）；
- 能力中心写操作的重试键（`CapabilitiesShared.tsx`），以及 Agent 接入凭据的请求标识（`CapabilitiesAccess.tsx`）；
- 规则效力面板写操作的重试键（`SourceAuthorityPanel.tsx`）。

## 修改

- 新增 `frontend/src/randomId.ts`：有 `crypto.randomUUID` 时直接使用；没有时用 `crypto.getRandomValues` 生成同格式的 RFC 4122 第 4 版 UUID。
- `api.ts` 原有的幂等键函数移入该模块，上述 5 处全部改用 `randomId()`。
- 测试：
  - `api.test.mjs` 新增一项：没有 `randomUUID` 时，上传队列仍能加入文件，并得到合法且互不相同的标识；同时扫描 `src` 下全部 `.ts`/`.tsx`，除 `randomId.ts` 外不得直接调用 `crypto.randomUUID`（把任一处改回即失败）。
  - `api.test.mjs` 加载 TypeScript 模块改为 esbuild 打包，以便解析模块间的相对导入。
  - `capabilities.test.mjs` 的源码断言改为 `request_id: randomId()`。
