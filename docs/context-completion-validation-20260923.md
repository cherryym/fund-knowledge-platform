# 原文关联补全与 Qwen 证据组重排

日期：2026-09-23。范围：通用 `universal` 答疑读取链路；不修改原文、既有分段、向量指纹、审核状态或历史答案。

后续真实验收发现泛书名触发全库补查扩散，现已收窄为精确跨文档引用自动补查；同文定位缺口/仅书名提及保留提示及模型主动阅读。并增加独立业务主来源通道，见[业务视角与主来源阅读](business-reading-focus.md)。下方合成测试成绩不代表修复前的真实答案质量。

## 实现

1. 命中小节按已有 v3 目录读取。编号子步骤存在同组兄弟步骤时，补读所属条/编号事项；不依赖问题中的“流程/步骤”关键词，不自动升级到整章/整本。
2. 读取父级导语中的引用，沿简单、复合、相对编号及可精确定位的附件引用继续补全。原块 ID、字符偏移及 Hash 保持绑定；循环引用通过已访问集合终止，不设固定深度截断。
3. `《文件》第X条…` 仅在当前授权目录唯一精确标题匹配后补读。重读仍检查 ACL、版本、扫描与 Hash。相似标题不是替代证明；同名歧义不猜选，无章节定位不自动展开全册。
4. 缺失引用自动本地补查，同一未变化检索表达每轮咨询只查一次。候选只作导航；未定位、不可读、歧义、较宽上下文分别记录。生成模型仍可继续 SEARCH / READ / READ_SECTION / READ_FULL，不增加思考总时限。
5. 已选内容及显式/已登记依赖组成证据组，调用已配置的本地 Qwen3-Reranker-4B 排序；不以分数删除必需依赖。失败保留原序、全部资料并显示真实状态。同请求内按原文、身份、查询及模型配置摘要复用相同排序。
6. 多轮补读的所有未发送原文累计后再分包，防止只发送最后一轮新块。来源在模型等待前后、最终交付及结果读取时继续重验。
7. 执行记录新增关联补全数量、补查次数、剩余缺口、实际重排状态及逐条引用详情。轻量进度只返回计数，失效结果隐藏完整诊断。缺口产生 `SOURCE_CONTEXT_GAPS` 提示，不因缺口吞掉其余有效答案。

## 局限和判定范围

- `OBSERVED_REFERENCES_CLOSED` 只说明当前已读材料里被识别的显式引用已闭合，不是全库 Recall=100%、完整业务流程或专家审核通过。
- 自然段的“第一款”不能从 PDF 断行硬猜。结构不能精确表示时，可补读完整所在条并记录 `broader_context`；不能冒称精确款已找到。
- 未登记的隐含业务前提、别称、无法识别的引用、OCR 错字及跨制度适用性仍需要模型/人工查证。图谱 PROPOSED 关系不升级成事实。
- 本轮未重建索引，`semantic_sections_v3` 的投影语义、指纹和现有向量保持不变。
- 旧 `adaptive`/legacy 阅读方式保留；新补全是当前 `universal` 路径，不宣称所有旧引擎同时升级。
