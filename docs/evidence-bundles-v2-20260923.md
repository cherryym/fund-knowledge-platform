# 完整证据组检索 V2：阅读覆盖、独立根排序和精确去重

日期：2026-09-23。范围：当前 `universal` Wiki + RAG 路径。当前阶段为本地工程实现与离线验证，不是金融业务正确性或生产SLA认证。

## 本轮改变

1. 逐个追踪模型公开计划及后续 SEARCH 的查证方向。路由保留每个方向的最佳候选及最佳原文候选的**标识和锚点**，不把原文或查询文本塞入跨请求路径缓存。
2. 阅读账本只在当前目录、确切版本/资源身份、实际已读原块匹配后记录 `SOURCE_READ`。候选命中、部分锚点已读或单独Wiki不算原文已读。Wiki必须有已登记CITES及确切原文块的实际阅读记录。PROPOSED、同名猜测、仅文档级链接不关闭原文阅读缺口。
3. Wiki占据首批候选时，可以先补读该方向已召回但尚未阅读的原文锚点，走原有完整小节与真实依赖读取链路，不额外调用生成模型；每个不变的缺口仅尝试一次，不能无限反复展开资料。无候选则向模型和用户保留明确缺口，允许模型改写搜索，不因部分缺口吞掉全部有效答复。
4. 证据组先按根来源自己的已读内容重排，再附带完整依赖。共享的高相关基础条款不再被拼进每个根并给无关根提供分数。全部已选来源、依赖、低分原文仍保留，不使用分数作为效力判断或删除门槛。
5. 同一次咨询的根来源分数按完整正文、问题、版本块Hash/证据标识及模型配置复用；新补读内容只使对应来源失效。权限、来源Hash和取消状态继续在等待前后复验，不缓存授权。
6. Qwen每次批次内部按**完整指令化token序列**复用相同窗口计算，结果散回全部原候选；不同问题不合并、不改变token窗口/覆盖/模型/精度。无跨用户、跨咨询推理缓存。
7. 智能答疑的执行记录新增“查证方向与原文阅读”，区分未找到候选、候选未读、仅Wiki和已读原文。实时进度仅回传计数；终态返回完整账本，来源撤权后隐藏；缺口警告在历史答案重渲染时保留。

## 明确不等价

- `SOURCE_READ` ≠ 引文支持结论 ≠ 规则现行适用 ≠ 业务问题已完整解决。
- 账本范围是**本轮计划/查证表达**，不能识别规划模型根本没提出的所有隐含业务事项，也不是全库Recall=100%。
- 根相关性分数只决定先后，不证明根或依赖正确。超长单来源仍按完整窗口评分、以最大窗口分数发现相关内容；没有声称解决所有长文评分偏差。
- 无候选不等于全库不存在；单次未变检索不自动重试，模型仍可自主SEARCH/READ_SECTION/READ_FULL。
- 没有重新切分原文、重建/删除向量、修改知识发布或效力状态、切换模型、压缩思考时间、重写历史答复。
- 已交付RAR是冻结快照，本轮不修改该RAR，不能说旧包自动包含V2。
