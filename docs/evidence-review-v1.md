# 已读来源约束与答复结构核对 V1

此模块为通用 Wiki/RAG 链路补充“来源定位正确但结论仍可能错误”的诊断。它不是新的法规库、完整语义蕴含模型或专家审批系统。

## 生成前

`evidence_review.prepare_source_review`只消费本轮已读、E编号无歧义、原块正文Hash匹配的记录，不扩大权限或另发模型请求。

- 按已登记阅读策略区分管理员指定主来源、核心目录检索候选、基础规则、辅助资料。核心目录命中不再在阅读说明中被一律称为必须引用的直接依据。
- 显式指定主来源优先展示；其他完整材料仍保留，不删除候选或必要依赖。
- 保留已登记适用条件、效力状态、生效/失效日期与原文限定的E编号。标题年份仅是线索，不据此自动判定法规废止。
- 同时出现多个来源的全价/净价口径时，要求核对日期、主体、市场与品种；不把两个不同条件的合法口径自动判成矛盾。
- 对已读连续原文中的日期标题、模式、显式“当日为”事件及部分动作提取结构线索；对连续分录同侧标记给出原文/节选异常提示。

数据以明确标记的JSON随原文进入现有综合请求。它不新增推理轮次、硬JSON答案合同、思考时限或固定答复字数，不替代完整原文。正文仍属于不可信资料，不取得系统指令或执行权限。

这里“不新增推理轮次”指不引入独立的收费核验模型调用；约束数据仍会增加输入长度。若总材料超出某提供商的实际上下文容量，既有分包阅读机制仍可能增加调用，不能承诺任何资料规模都固定只调用两次。端到端时间与新生成质量仍须真实测量。

## 生成后

`review_answer`将有限结构性发现绑定到答复SHA、文字跨度及冻结E引用：

| 检查 | 行为与边界 |
|---|---|
| 显式事件日期 | 对同种日期单位、可识别模式、已引用的源事件作比较；缺模式且多个日期可解释、引用未登记、源块不连续时不猜测。 |
| 分录方向 | 同一被观察分录组只有两个以上同侧借/贷标记时提示核对；不计算缺失金额，不猜正确科目，不改原件。 |
| 价格口径 | 多源引文同时含全价/净价时提示适用边界比较，不自动选择现行版本。 |
| 扩大适用 | 原文带有限定，而正文出现“因此/同样/所有”等扩张线索时提示复核，不禁止有依据的综合推断。 |
| 登记适用条件 | 已知不匹配的材料不能悄悄作为直接适用依据。 |

原始Markdown始终保留。`NO_STRUCTURAL_FINDING`仅表示这些有限规则没有发现疑点，**不是PASS、不是完整语义审核、不是业务可执行**。无法用这些规则识别的隐含前提、复杂跨句关系、金额和公式仍须独立验证。

## 展示与历史记录

新诊断经`model_snapshot.evidence_review`展示。关键日期/分录疑点置于正文前；原有引用和全文继续可读。普通口径/范围线索与具体严重疑点区分，不能用一个“处理完成”标签掩盖。

历史答案GET可在当前访问核验通过后，用原运行冻结E映射重新计算只读诊断；**不写回历史正文、生成时间或调用数**。来源失效/撤权时不返回诊断。无完整历史E映射时不从今天的全局目录猜补。

## 引用标点修复

闭合单条引用后的说明性破折号与真实区间分别解析。`【E41】——说明`不是缺端点区间；`[E1]—[E3]`仍按区间核验。非法编号、缺端点、反序、缺号、代码遮蔽等告警保留，不能靠过滤告警制造通过。

## 测试与真实验收

专项合成测试覆盖正常/错误日期、模式歧义、读块缺口、否定/引用文字、多行分录、正常借贷与替代分支、Hash变化及来源撤权。实际worker测试验证约束进入现有综合调用、结果保留及GET只读性。

使用获准冻结答案可以离线回放发现，但这不等于生成模型已经能产出修正后的业务答案。新的真实咨询和完整质量/速度对照需要相应调用额度，不得把旧失败答案重新标成成功。
