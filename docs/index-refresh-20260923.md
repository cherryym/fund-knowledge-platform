# 重建完成后的索引状态更新

日期：2026-09-23。用户要求重建后必须更新，并且可以直观看到新索引生效。

## 实现

- 状态接口新增 `index_snapshot`：实际核验时间、当前可读目录的索引代次、最近写入时间、当前账号/空间/确切检索方案的最近终态作业和最近完整重建。
- 代次由当前授权目录中、已通过原有Qdrant完整性核验的 `(version_id, projection_id)` 集合与嵌入指纹生成。它不是数字计数，也不是全平台统一版本号。同样资料完整重建后，即使数量相同，实际投影变化仍会产生新代次。
- 将当前可读版本逐个绑定到最近完整重建的作业ID/attempt/源元数据签名。只有作业计数完整成功、当前目录全部已有有效索引、且所有当前投影都来自该次重建，才显示“重建已生效”。失败/取消/计数缺失、源变更待同步、向量不可用或混合后续代次都明确区分。
- 任务结束后自动重新GET核验状态；等待和失败均有提示，不会仅凭任务SUCCEEDED就确认新索引生效。清除旧检索结果，不自动再检索或重建；用户可用现有检索词重新提交。
- 最近作业结果由后端提供，刷新或返回页面不会丢失；上方改为“当前目录索引覆盖”，下方明确“全部处理版本（含历史版本）”，不把历史数量冒充当前覆盖。
- 状态GET仍只读且no-store。最近作业只查当前owner、space和完整冻结profile绑定，不透传原始payload，不暴露其他用户任务。SQLite/Oracle/OceanBase使用统一SQLAlchemy查询，无新增表或不可逆迁移。
