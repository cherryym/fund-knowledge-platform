# 已知限制与验收边界

开源发布意味着代码可以查看、运行和改进，不意味着生产环境或金融结论已经认证。

## 答案准确性

- 可能出现未登记引用、相关但不支持主张的来源、适用条件遗漏、来源版本选择不当或跨来源推断错误。
- E编号可定位、Hash一致、模型成功结束、自动测试通过，都不能证明语义支持及专业适用性。
- 已知真实开发验收曾出现技术完整返回但仍有未知引用的情况。公开仓库不附私人咨询/原文证据，不能把该个案包装成公开准确率。
- 正式业务依据需要具备对应效力、发布及资格；待核验资料只能有条件参考，不因为批量生成而自动升格。

## 性能

- 没有全业务20秒保证。一次完整答复可能包含独立规划、多查询、重排、补读和多次模型请求。
- 公开计划/路径缓存有命中条件、期限和失效检查，不是所有新问题都变成一次请求；有技术告警或失效的运行不能提供计划缓存。
- 流式公开预览按协议条件提供，非公开中间事件会使预览撤下；正文必须经过最终检查。
- Wiki全量授权加载与图谱大规模交互须在目标数据量、浏览器、设备及并发下验证，不能只拿idle帧率作保证。

## 生产依赖

- Oracle/OceanBase有方言与配置实现，目标真实实例和机构生产负载仍需单独验收；未提供实例的测试是SKIP，不是PASS。
- 默认SQLite、demo登录、basic扫描和loopback入口都是开发路径，不允许直接充当生产方案。
- 扫描PDF、复杂表格/公式、印章/扫描页等解析质量需要独立复核，未提供通用高精度OCR承诺。
- 外部OIDC、扫描器、S3、Celery、Qdrant和备份恢复需按部署环境联合测试。
- Codex身份/文本隔离与模型供应商协议可能随版本变化，需要跟踪官方行为，不能依赖公开仓库携带登录态。

## Agent能力

已有能力定义、来源绑定、步骤依赖、试运行/指导运行、产物回报和人工检查。尚不等于通用自治执行平台：没有财务系统任意写入器，没有自动专业审批，没有所有退回补正场景的自动重开保证。

## 发布范围

发布完整应用源代码、测试、契约、部署模板和所需通用工具；不附真实数据、历史截图/咨询、密钥、权重、私有运行配置，也不附仅针对原本机固定资料的批量导入、发布、删除或一次性清理脚本。后者不是通用应用功能，公开后盲目运行存在风险。
