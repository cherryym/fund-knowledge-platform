# 默认检索方案自动预热与常驻

日期：2026-09-23。适用于本地 transformers 嵌入 + local 重排的组合，包括当前Qwen3-Embedding-4B与Qwen3-Reranker-4B。

## 行为

- `FKB_RETRIEVAL_WARMUP_MODE=auto` 为默认：API启动后后台准备默认方案；Celery子进程初始化自己的运行时并启动同样的后台准备。非默认方案保持按需，第一次查询或显式按钮可准备。
- 可配置 `on_demand`（查询/按钮触发）或 `disabled`（兼容原加载策略）。不改变模型、切分、嵌入指纹或索引；HTTP/fastembed/hashing方案不自动外发探测请求，返回NOT_APPLICABLE。
- 自检先用一条固定合成文本执行本地嵌入并核对维数/数值，再用两个固定合成候选执行重排并核对输出。全部通过才READY/self_tested；配置存在、文件尺寸正确或模型对象存在都不等价于推理就绪。自检不证明金融专业准确性。
- 同一运行时只执行一个准备任务。并发查询等待同一任务；进程内多个方案的准备串行排队。单个咨询取消不会取消公共准备；没有固定的思考/加载总时限。
- 成功后保留原生模型直到运行时/进程关闭，不在每次查询后卸载。关闭先等待正在执行的本地内核结束，再释放模型。进程重启会重新预热。
- 失败记为FAILED，保留安全错误码，不记录异常中的路径、token或原始正文；查询不自动反复准备，也不会因预热失败进入跳过重排的答疑路径。编辑者/管理员可以显式重试。

## 状态与界面

- `GET /retrieval/model-runtime` 是新增的已审阅只读能力，只查当前账号有权访问的空间、指定方案和当前进程状态；不触发加载，不读取业务正文。
- `POST /retrieval/model-warmup` 复用CSRF、幂等、空间编辑权限和服务端冻结profile选择。前端不能提交模型路径、服务地址或权重；跨进程重载后的旧幂等回执拒绝重放。
- 管理页显示准备中/加载与自检中/推理就绪/失败，只在加载期间轻量轮询，失败停止自动轮询并给重试入口。页面顶部原“模型运行前提就绪”改为“模型文件与依赖已检查”。
- 新咨询记录自己实际执行进程的准备回执和进程号；API的READY不冒充另一个Worker已就绪。咨询取消、来源权限和版本核验保持原边界。

## 验收边界

测试使用合成数据和本地模型，禁止调用收费生成模型或读取其他项目凭据。全量/本机结果与实际准备耗时在接入完成后补充。本轮不重建实际业务索引、不发布知识、不重打已有RAR。

每个API/Worker进程分别持有模型权重。部署时必须按进程数规划内存，不能把单个Mac MPS进程的耗时或内存表现当成Windows/Oracle/Linux CPU生产性能承诺；共享模型服务仍是独立的后续架构选择。
