# 模型服务接入

## 生成模型与检索模型不是同一个配置

“我的模型”管理生成模型连接，用于Wiki、公开查证规划和综合答复。嵌入/重排用于发现材料，配置见[检索手册](retrieval.md)。接入云端生成模型不要求部署本地生成模型；离线Wiki资料管理也不会自动产生模型费用。

## 厂商API与网关

1. 在“我的模型”新建连接，选择厂商/网关及兼容协议。
2. 填写官方或已授权服务地址，使用本人的API密钥或明确的环境变量引用。
3. 加密托管须由服务端配置独立`FKB_PROVIDER_MASTER_KEY`；不要把明文密钥写进源文件或提交记录。
4. 同步模型目录、测试连接，并检查当前账号是否真正有权调用该型号。
5. 根据资料性质明确允许文档上下文传输，再主动发起业务操作。

支持的协议实现包括OpenAI兼容Chat Completions、Responses、Anthropic、Gemini、Ollama与受控Codex文本桥接。协议参数、结构化能力和结束原因按适配器检查；厂商名称或图标并不证明协议完全兼容。

OpenRouter等网关需同时考虑网关与实际上游服务的费用、资料处理和路由规则。预置旗舰标识只是目录属性，不保证当前可用、模型最新或账号授权。切换模型不会把不同嵌入空间的向量自动转成兼容结果。

## 本地服务

Ollama、LM Studio及兼容HTTP服务需由使用者自行部署、配置可达地址并选择实际提供的模型。本项目不附模型权重，不会在未明确准备的情况下后台下载模型。

服务端会限制本地地址和外部请求目标，避免任意地址成为内网代理。远程使用时不要把开发HTTP端口直接开放公网；配置受控网络及认证。

## Codex官方登录适配

本仓库包含独立身份桥接、官方登录状态管理和受限文本推理代码；**没有携带任何可复用的登录态**。

- 应用使用自己的运行/加密存档目录，不读取或复制宿主Codex的授权文件。
- 需针对官方可执行文件版本、Hash、角色消息通道、模型目录和零工具文本边界完成独立验证，配置才会允许推理。
- `configure-codex-oauth.py`、`configure-codex-text*.py`及探测脚本是受控操作辅助，不是绕过厂商访问权限的万能登录器；不要直接复制他人host.json/profile。
- 适配器当前约束可从`codex_bridge.py`/`codex_text.py`查看。未来版本变化可能需要重新验证；登录成功与文本推理可用是两种状态。
- 订阅访问不等于通用API余额，能否调用某型号以官方账户实际权限为准。服务条款、组织政策和数据出域许可由使用者自行核对。

## 出错时

先看连接和任务的具体阶段/错误码，再判断权限、网络、额度、协议、上下文容量或来源变化。保存配置、同步目录、真实生成和专业正确性是不同验证层级。

不要把失败响应伪装成摘录成功，不要静默换模型；结果不确定时也不要无限自动重试。引用缺失可以显式告警并保留可展示正文，但不得猜造文档定位。
