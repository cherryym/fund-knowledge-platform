# 下一轮通用RAG修复（2026-09-24）

本轮针对真实验收暴露的来源适用边界、答案与原文不一致、异常分录传播和初轮重排成本实施修复。没有新增收费生成、改动模型账号、文档原件/效力/审核状态或重建向量。

## 实际修改

1. **引用语法**：闭合单条引文后的普通破折号不再被误认成缺端点范围；真正的范围、缺号、非法编号、代码屏蔽等检查保留。不是通过删除告警来修复。
2. **阅读组织**：管理员显式指定主来源优先于宽泛目录检索候选；候选、基础规则和直接依据分别描述，不把检索排名当作适用性认证。完整已读材料仍保留。
3. **生成前的来源约束数据**：从实际已读、Hash绑定的原文提取有限的日期/模式、适用边界与分录疑点，同现有综合请求一起提供；不新增一轮模型调用或硬JSON答案门槛。
4. **生成后的结构核对**：将可识别的引用事件日期冲突、同侧分录组、混合价格口径与扩大适用线索绑定到答复SHA和E来源；正文不被改写或整篇拒绝。无发现也不等于专业PASS。
5. **可见反馈**：具体疑点在正文前显示；权限失效时隐藏诊断。历史GET只作当前权限下的冻结来源核对，不写回旧答案或伪造新的生成时间。
6. **重排输出头实验与不采纳决定**：实现只投影两个原模型标签的实验，保留完整decoder、所有查询/候选/窗口、原dtype及分数定义。虽然已完成配对的评分/排序相同，但独占规模组为92.099→97.639秒，没有证明整体收益，因此实际默认仍保留原末token全词表路径，不以局部计算量下降冒充端到端加速。实验和批量对照的边界见[专项记录](qwen-label-head-20260924.md)。

实现入口：`backend/fund_kb/evidence_review.py`、`wiki_answer_job.py`、`api_consultation.py`、`source_reading_policy.py`、`business_reading.py`、`wiki_answer_content.py`和`qwen_reranker.py`。前端入口为`EvidenceReview.tsx`及`ConsultationPage.tsx`。

## 不是单题答案补丁

检查以来源结构、显式模式、冻结E引用和登记策略为输入。测试使用合成办理日、主体、科目及模式，没有将真实问题、真实资源ID或一套期货/回售标准答案写入公库。

价格口径、适用范围和单侧分录等提示只是有限规则的复核线索。复杂条件、跨句隐含前提、完整金额平衡与法规时效仍需专业核验；不会自动修改原件、审批替代事实或把推断变成现行制度。

## 离线回放与验证边界

冻结失败答案在本机私有输出中回放：引用破折号误报消除；原文与答案的显式日期错位、异常分录和价格口径比较可被定位，答案原文保持不变。此回放没有重新调用生成模型，**不能算作新模型业务答案已通过**。

工程验证包括合成模块反例、真实worker路径的假模型回调、API权限变化/只读历史投影、前端显示与撤回以及构建。完整后端首轮为4916 PASS / 8 SKIP；最终专项与本机接入结果在交付记录中列明。Oracle/OceanBase外部实例等跳过项不算通过。

前端全量第一轮发现新增样式未限制页面作用域，已修复；下一轮全部断言通过但咨询测试进程出现120秒清理超时，仍记失败。测试夹具随后仅模拟当前轮询实际拥有的setTimeout/Date，不替换浏览器RAF/GSAP拥有的setInterval，保留旧性能基线专用选项；独立资源检查无剩余定时器/worker。不通过提高时限、强退进程或删除断言掩盖失败。完整复验结果单独记录，不能据一次独立通过声称所有偶发资源问题已永久解决。

## 接入原则

仅将白名单源码、测试和说明同步到已授权本机应用，逐文件核对已知旧Hash，原文件可恢复备份；检测到未知改动立即停止覆盖。重载前确认没有运行/排队业务任务。原文、引用、Wiki、图谱、索引回执和检索配置摘要需保持一致。

本轮不自动提交/推送Git，不生成新的RAR、不部署Windows/Oracle生产环境。之前的真实咨询额度已按保守口径用完；后续业务答案与完整速度验收仍需要新的调用授权，不能自动重试直到出现合格答案。
