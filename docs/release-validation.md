## 完整性与发布范围

逐文件比较：102个后端业务源码文件、142个前端源码文件、3个数据库迁移文件均与整理前应用内容一致；没有为了开源删掉核心功能。发布另补齐中文文档、许可、安全政策、开发/容器入口、通用双检索配置辅助和CI。

## 发布安全

独立Gitleaks 8.30.1扫描使用默认规则、100%输出脱敏。发现的两个测试样本分别是非功能性合成Token与拼接的私钥canary，已逐行注释说明；没有全文件或全目录白名单。提交前还检查Git跟踪文件、个人绝对路径、运行产物、文件大小与文档链接。此类检查不是完整DLP或安全认证。

## CI与生产边界

GitHub CI自动运行发布边界、后端/MCP、前端和Compose构建/启动。每次提交的真实结果以[Actions](https://github.com/cherryym/fund-knowledge-platform/actions/workflows/ci.yml)为准，不将“已配置CI”写成“CI已通过”。本机未安装Docker，容器验证由GitHub受控演示任务完成。

本轮没有目标生产数据库、机构身份服务、扫描器、容灾或金融专业准确性验收；不得把开源发布、页面可用和测试通过称为生产就绪。

## CI可移植性补充

首轮GitHub CI的发布检查及Compose构建/启动通过；前端在一组测试完成后未退出，日志仍有编译器子进程。该轮主动取消以保留诊断，不记为通过；后端当时正常推进到约87%，同轮被取消，不记为后端失败或通过。

后续显式释放前端测试拥有的esbuild服务，增加CI测试超时报错而非强制成功退出；后端118个测试文件按排序分成30/30/29/29四个互斥组，覆盖不减少。Actions引用改为经上游tag核对的固定提交SHA。这些是发布/测试适配，不变更业务实现；因此上文142个前端文件的一致性比较对应首次发布快照，后续只有测试资源清理例外。
