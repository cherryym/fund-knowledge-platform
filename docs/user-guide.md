# 使用指南：从文档到可调用能力

## 1. 建立知识库

开发模式使用页面上的合成身份登录。正式环境使用配置好的OIDC身份。进入“设置”创建个人或团队知识库：个人库由本人管理，团队库按成员/角色协作。先明确资料保密范围与允许使用的模型来源，再导入内容。

## 2. 整理来源文档

在“文档中心”创建分类及子分类，例如：估值与核算 → 法律法规 / 估值指引 / 交易规则 / 内部制度 / 操作手册。示例只是组织建议，不是法规效力判定。

上传PDF、Word、Excel等原件后，检查扫描、解析状态和版式；扫描件的OCR或表格/公式解析不能默认正确。可以在原件预览与解析内容间核对，也可以在线编辑合适的文稿版本。替换原件使用“上传新版本”，不要用编辑器覆盖历史附件。

## 3. 构建Wiki

先在“我的模型”配置自己的连接，选择可访问的型号，并明确同意向该服务传输本次资料。然后从文档入口构建知识，按内容选择专题、原子规则、场景或SOP类型。

生成结果是待核验内容。检查：原文定位、适用条件、日期、例外、跨文件引用、术语定义和遗漏。来源资料未通过正式准入时，可使用待核验流程浏览/编辑，但不能自动成为正式制度依据。

## 4. 浏览知识与图谱

“知识空间”提供分类、标签、搜索、正文、`[[双链]]`与反向链接。点击来源引用回到确切文档版本。全局图谱用于概览，局部图用于围绕某一知识点钻取；可拖拽、缩放、平移、配色和调整图谱高度。

图上的边不是天然正确的因果关系。待核验的模型语义关系、人工关系和真实来源引用应按界面状态区别使用；主题相似不能自动当业务依赖。

## 5. 发起咨询

在“智能答疑”选择模型后输入问题；选择会在该用户下保留，直到主动切换或清除。Enter发送，Shift+Enter换行，输入法确认过程不会被当作发送。

按需要补充业务日期、产品/资产类型、交易方向、实际发生阶段、已取得单据和已知异常。不要把不确定事实填写为确定值。程序会显示规划、检索、读取和生成阶段；你可以取消，不需要关闭网页。

读取答案时区分：直接规定、跨来源推断、操作建议、示例和缺口。点开关键主张的引用核对原文、版本与适用性。UNKNOWN_CITATION或其他告警不能忽略；“模型已调用”“技术COMPLETED”不等于答案正确。

## 6. 维护规则效力

在“设置 → 规则效力”查看已识别/已有的替代关系，打开预填要素后核对旧来源、后继来源、证明原文、起始日期、范围和原因。存在歧义或缺项时补充信息，不仅凭上传日期判断哪份制度更新。

确认只登记该替代事实，不代表整份新文件现行有效，也不等于独立专家审核。来源变化后需要重新核对，不能无条件延用旧事实。

## 7. 沉淀Agent能力

进入“Agent能力”：

1. 定义触发场景、能力说明、限制及必要输入。
2. 绑定适用来源的确切版本与范围，不能以空绑定开放全库。
3. 定义步骤、依赖、角色、工具要求、输出字段和核对项。
4. 将高风险或最终核验步骤设为人工检查。
5. 保存草稿，先做试运行，确认来源/依赖/输入和返回结果，再走复核发布。
6. 如需外部Agent，创建本人单库、最小scope、有期限的接入凭据，并按[接入文档](agent-connector-v1.md)配置。

能力包可以导出为`SKILL.md`、`workflow.json`和接入说明，但导出不等于自动安装或授予其他系统权限。Agent回报步骤后，人工检查仍由网页用户完成。

## 8. 更新、删除与恢复

资料更新后，复查关联Wiki、来源与索引状态；不同检索profile分别维护。删除的内容进入回收站，恢复和清除由后端核对权限。保留策略、法律保全、版本及引用依赖可阻止永久清除；不要为了让按钮可点而绕过这些检查。
